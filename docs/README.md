# OctoAcme Project Management Docs

This folder contains the core project management guidance used by OctoAcme to move work from idea to delivery and continuous improvement.

## Project management process overview

OctoAcme uses a simple lifecycle to manage projects consistently across teams:

1. Initiation
   - Validate the business need, stakeholders, and success criteria.
   - Define the project one-pager, key milestones, risks, and resource needs.
   - Decide whether the initiative is approved to move into planning.

2. Planning
   - Turn the approved initiative into an actionable plan, backlog, and timeline.
   - Prioritize work, estimate scope, define acceptance criteria, and document the Definition of Done.
   - Identify dependencies, risks, and release milestones.

3. Execution and tracking
   - Deliver work in visible increments with clear ownership and regular team communication.
   - Use standups, project boards, PR review workflows, and checklists to track progress and blockers.
   - Monitor velocity, burndown, and key delivery signals.

4. Risk and communication management
   - Maintain a risk register, identify dependencies, and escalate issues through the agreed paths.
   - Keep stakeholders informed with regular updates and a single source of truth for status.
   - Use escalation frameworks for team, product, and sponsor-level issues.

5. Release and deployment
   - Confirm readiness through CI, security checks, smoke tests, and release notes.
   - Standardize rollout, verification, and rollback/incident response steps for production changes.

6. Retrospective and continuous improvement
   - Capture lessons learned after each sprint, release, or milestone.
   - Turn improvements into action items with owners and due dates, then review them in ongoing project communication.

Together, these steps create a repeatable project rhythm focused on customer value, clear ownership, iterative delivery, and evidence-based decision-making.

## How to use these docs

- Start with the Project Management Overview for the high-level lifecycle and roles.
- Use the initiation and planning guides to validate ideas and create a delivery plan.
- Refer to the execution, risk, release, and retrospective docs during active delivery and after milestones.
- Keep project artifacts updated in the repo so the team has a consistent, shared source of truth.
